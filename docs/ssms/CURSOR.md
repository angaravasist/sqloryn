## Paste into Cursor Agent

> Own delivery of SQLoryn, an installable, SSMS-familiar SQL Server studio for macOS. Continue the existing PR #7 work as one integrated PR. Check its live state, local branch, base, tip and working tree first. Preserve existing edits. If the PR has already merged or closed, report the discrepancy before writing to its remote branch. Read AGENTS.md and its required documents, then docs/ssms/PARALLEL-TDD.md, PR7-ACCEPTANCE.md, DESIGN-RESEARCH.md and README.md in that directory. Use the stable CAP and SURF IDs. Check the current implementation for each finding before reproducing it. Work through all feasible requirements in this session. Keep collecting evidence while other workers implement.
>
> **Coordinate the work.** One integrator owns shared command routing, package and lock files, CI, the integrated build and evidence documents. Before spawning writers, review and checkpoint the intended local handoff files on the feature branch so fresh worktrees contain them. Leave unrelated edits with their owner. Use independent local worktrees for writers. Start concurrent work on credential isolation, generated SQL and row-edit safety, document/export integrity, and native shell/appearance where files permit. Agree who edits a shared file before dispatch. Pull further work from all 18 queues as capacity frees. Each worker receives its CAP/SURF or finding IDs, files or symbols, neighbouring contracts, positive and negative outcomes, test command and evidence expected. Review worker diffs and incorporate only their intended commits. Workers do not push independent PRs.
>
> **Deliver the full product scope.** Reconcile the action inventory with the pinned SSMS sources, product catalogue and feature matrix. For each action establish its actual entry point, applicable service, permissions, target, licence and output before implementing or recording an alias, external prerequisite or version-specific exclusion. Implement through the existing UI, Core and provider boundaries. Cover daily editing and Object Explorer through schema, data movement, administration, security, diagnostics and service-specific tooling as documented in the ownership table. Where infrastructure blocks integration, continue implementing the independently testable behaviour, name the missing fixture and leave live support unverified. Keep the requested AI query assistant deferred.
>
> **Use TDD for every behaviour change.** Reproduce a bug or add a failing assertion at the normal command boundary. Record which assertion failed and why. Implement the smallest complete path, rerun the test, then refactor and run adjacent tests. Include denied permission, stale target, interruption, cancellation or partial failure where relevant. For example, change a profile endpoint while an old Keychain read is pending and assert that the old secret never reaches the new target. Force a conflict on row two and independently verify that row one is unchanged. Feed generated DDL an identifier containing a newline and prove only the intended statement can run. Verify effects with an independent connection or file read where the claim requires it. Track every one of the 18 review findings through closure.
>
> **Ship the Mac experience.** Apply the design study and all eight desktop journeys. Give first launch a clear Connect action, correct system menu and original app icon. Use system appearance and accent, native keyboard conventions, visible focus, accessible names, resizable panes and a readable dense grid. Connect a synthetic fixture, navigate to a table, author and run a selection, inspect multiple outcomes, save or export and recover safely. Review the packaged app in light and dark appearance at laptop size. Test keyboard and VoiceOver paths on available hardware. Capture sanitised screenshots from the actual build. Record launch, large result, large document and cancellation measurements with the fixture and hardware.
>
> **Code to the repository standard.** Follow .editorconfig, nullable checks, warnings as errors and locked dependencies. Reuse proven helpers and keep vendor, Keychain and file operations outside views. Parameterise values, quote identifiers, bound reads, preserve numeric precision, check document/session ownership after awaits and distinguish uncertain outcomes. Preview destructive effects and require explicit confirmation. Preserve users' files on partial failure. Review dependency licences, redistribution, security and platform availability before adoption. Keep existing CI protections and minimise permissions.
>
> **Keep it usable by the next agent.** With each change update the relevant spec, matrix and STATE. Record capability/finding ID, user entry point, code symbol, test name, command, tested commit, platform/target, observed result and remaining gap. Update architecture or ADRs for changed boundaries, threat model for changed data flows, dependency inventory for new packages, and TESTING/WALKTHROUGH for changed commands or journeys. Use synthetic examples. Never copy credentials, real SQL contents or machine-specific endpoints into the repository or a worker prompt.
>
> **Integrate and verify.** Run the locked Release build, both assertion executables, Python tests, preflight and packaging from docs/TESTING.md on the integrated tree. Run the eight journeys, architecture-specific checks and disposable SQL tests only where authorised. Keep the former Windows SSH path closed. Record skips precisely and continue unrelated work. Invoke sqloryn-verifier for independent review. Fix reproducible defects and rerun affected checks. Inspect hosted checks for the actual integrated SHA. Return the built app path and install instructions, what a user can do, screenshots, finding dispositions, feature evidence, outstanding risks and specific maintainer decisions. Keep the PR reviewable. Leave merge, signing credentials, publishing and spending to the maintainer.
