Baseline reviewed on 3 November 2026 at commit 96f742e. Findings and tests below are requirements to recheck on the integrated head. [Reviewed source](https://github.com/angaravasist/sqloryn/tree/96f742ee8ef7ea710ca5dc1854cf222af4cf46d3)

File and symbol references below are relative to the reviewed tree. Treat 1–6 as immediate safety/correctness gates. Ship the user-facing work in the same PR.

| 1 | **Generated SQL injection.** TableDesignSql.PreviewAlter embeds a quoted column name in a single-line warning comment. | 2 | **Remembered password can follow a changed destination.** ConnectWindow.OnProfileChanged fills PasswordBox asynchronously; OnConnect independently reads editable server, port, TLS and login fields. A trigger producing results can undermine that check. Some column types are omitted from the optimistic predicate despite the UI promising the row still matches. | Require a supported key plus dependable version check; refuse unsupported cases. Refresh key metadata, use typed parameters and an owned transaction, validate every write before commit. A conflict rolls the set back. Unknown commit outcome requires reload. Test triggers, composite key, concurrent edits, disconnect at commit and read-only/computed columns. |

## Design direction and interaction specification

Use SQL Server terminology and object hierarchy from SSMS. Use Azure Data Studio as a historical reference for moving from editing to results. The Mac references carrying the greatest weight are Postico for server selection, TablePlus for the database workspace, Nova for editing, and Kaleidoscope for change review. Apple’s system conventions govern menus, windows, appearance and accessibility. See the research ledger for source links and all 56 individual comparisons.

1. **Install and first open.** User drags SQLoryn to Applications and opens it in Finder. Use a crisp original icon and consistent SQLoryn name everywhere. Create the useful window immediately; asynchronous profile lookup can follow. No forced onboarding, artificial delay, giant gradient logo, network probe or credential prompt. First-run hero fits in one sentence. Repeat launch shows recent profiles and documents only per privacy settings; databases never auto-reconnect or execute on launch. With no saved profiles, show the actions users can take now. Local files work offline.
2. **Choose a target.** A Mac sheet groups Connection name, Server, Database and Authentication; advanced port, timeout, TLS and lab pin are disclosed. Label each field permanently, keep validation near the field, make Return perform the safe default and Escape cancel. Do not reveal a saved secret when duplicating/changing hosts. After connect, expose profile and real database in the toolbar near Run. Show Production as text where the user has labelled it, not a colour alone.
3. **Daily workspace.** System menu bar; compact unified title/toolbar; collapsible Explorer; document tabs; editor; collapsible results drawer. Keep each document's target visible on tab switch. No permanent right inspector when nothing is selected. Sidebar search has explicit scope. Document/selection is a compact control beside Run. During execution reveal Cancel and elapsed time. When output arrives show first useful set and a single brief outcome such as “2 rows · 42 ms”; surface real errors immediately. A detailed message is one action away.
4. **Visual language.** System text for UI, readable monospaced code and tabular digits for values. Starting sizes 13 pt controls, 13–15 pt user-adjustable editor, 11–12 pt secondary labels. Use 4/8/12/16/24 pt spacing. A single meaningful divider between panes, no shadowed cards around working content. Accent for primary action/selection; reserve red for destructive/error. Respect increased contrast, reduced motion and system accent. Internal object IDs and legal/status caveats belong in details/help. Keep selection visible with inactive focus. Use text or symbols in addition to colour. Aim for 4.5:1 normal text and 3:1 meaningful UI boundaries/focus, then verify measured colours in both themes.
5. **Change review.** Editor results are read-only. A separate edit surface shows original/proposed values, number of rows and full target. Preview SQL and typed parameters without logging private values. Default safe action when destructive; no focus trap. Success, rejection, rollback and unknown commit are distinguishable. Close returns to the originating table/tab. Export uses a native save sheet and makes scope, destination and truncation explicit.
6. **Visual review evidence.** Capture actual running screens using synthetic data: first launch, returning profiles, connected editor/results, two tabs with different targets, errors/partial rows, designer/row conflict, settings and a narrow window. Show light/dark and keyboard focus. Record Finder/Dock identity and a short first-launch-to-results recording. Design mockups are reference only. Submit a visual slice early in the same PR; continue the other work without waiting for routine design gates.

## Integrated user journeys

| Journey | Observable result and required failure case |
|---|---|
| Install/open and identify | Both architecture bundles have the icon and expected plist; native arm64 launches offline. Check icon at small size, keyboard-only navigation and correct missing runtime guidance for a framework-dependent package. Separate Intel publish from Intel launch. |
| Connect and target | A user creates two profiles/tabs, connects, sees the actual target, changes one tab's DB without changing the other, forgets a saved secret and reconnects explicitly. Cover wrong password, pin mismatch, Keychain denial and a late async response. |
| Explore to query | Find a table, inspect columns/key, generate SELECT in a new correctly targeted tab, then execute. Test ambiguous/quoted names, restricted visibility, refresh after change and cancellation. |
| Author to debug | Open a script, find/replace, save, run a selection containing multiple batches/sets with a deliberate later error. Messages and editor locations identify the failing batch while prior rows remain. Verify quoted/commented GO, mid-script USE and two competing tab actions. |
| Results to file | Copy cells and export two distinct result sets without losing decimal precision or conflating NULL with empty. Cancel an export over an existing destination, verify the old file survives. |
| Design and edit | On disposable synthetic data only, preview/create table, refresh it, edit one keyed row, force a concurrent update and prove conflict detection. Attempt an unsupported edit and a denied operation. No unexplained writes. |
| Diagnose | Inspect visible database properties and security/activity, obtain an estimated plan for a permitted query, then test denied SHOWPLAN and an unavailable optional feature. Prove estimate does not perform a write. |
| Recover and exit | Cancel a long query, induce failure/disconnect, verify no replay, check script edits survive tab switch/failed save/quit cancellation, then clean up this run's files/resources. |
