# ADR-005 — SQL editor component: AvaloniaEdit

Owner: SQLoryn maintainer. Date: 2026-11-04. Scope: lexical colouring, line numbers and
go-to-line. Extends [ADR-003](003-desktop-avalonia.md). Provisional for the macOS preview.

## Decision

Adopt [`Avalonia.AvaloniaEdit` 12.0.0](https://www.nuget.org/packages/Avalonia.AvaloniaEdit/12.0.0) (`AvaloniaEdit.TextEditor`)
for the SQL editor in place of the multiline `TextBox`.

| Check | Result |
|---|---|
| Licence | NuGet metadata declares `MIT` (Avalonia Team; port of ICSharpCode AvalonEdit, MIT). Compatible with the project MIT licence. Retain the upstream copyright notice in any artifact. |
| Compatibility | Depends on `Avalonia >= 12.0.0` for `net8.0`/`net10.0`; the app locks Avalonia 12.1.4 on `net10.0`. Only one lock entry was added (no transitive packages). |
| Content | Managed DLL only (no native assets, no network code). Included built-in highlighter resources are unused; SQLoryn supplies its own T-SQL definition. |
| Supply chain | Direct reference locked in `src/Sqloryn.App/packages.lock.json` (content hash recorded); restore runs with `--locked-mode`. Package signature is NuGet-author-signed; inspect the publish output before any distribution. |

## What is delivered

- Line-number gutter (`ShowLineNumbers`), horizontal/vertical scrolling, undo/redo and standard keyboard editing from the component.
- Lexical T-SQL colouring: keywords, `--` and `/* */` comments, `'strings'`, `[bracket]`/`"quoted"` identifiers,
  `@variables` and numbers. The definition is generated by `Sqloryn.Core.TsqlHighlighting` (tested) with separate
  dark/light palettes, and is not a parser: it does not validate SQL or version-specific syntax.
- Go to Line… (Ctrl+G on every platform; Cmd+G stays reserved for Find Next convention) with `line` or `line:column`
  validation in `Sqloryn.Core.GoToLine`.
- `ScriptDocument` stays the source of truth: `MainWindow` copies `Editor.Text` into it on every change, tab switch,
  save, run and replace. Run reads the captured selection (`SelectionStart` + `SelectionLength`) so selection execution
  offsets are unchanged. Find/Replace now targets the `TextEditor` through the same `FindReplaceEngine`.
- Typing is fully local: no completion, telemetry or network call exists in the editor path.

## Limitations

- The `TextBox` placeholder hint is gone; the hint moved to the editor tooltip and run-mode label.
- VoiceOver behaviour of `TextEditor` is not verified; the control keeps `AutomationProperties.Name="SQL editor"` but
  AvaloniaEdit's automation support is untested here.
- Folding, completion, snippets, diagnostics squiggles and formatting remain unimplemented.
- Large-file responsiveness: Core line math over 2 MB is bounded in tests; the visual editor path is not measured
  in CI. See `docs/evidence` for manual numbers when recorded.

## Rejected alternatives

| Candidate | Reason |
|---|---|
| Keep `TextBox` + hand-built line-number column | Needs scroll synchronisation, no highlighting, and every future feature would duplicate editor internals. Kept as the documented fallback if AvaloniaEdit regressed. |
| `AvaloniaEdit` 11.x (`AvaloniaEdit` package) | Targets Avalonia 11; mixing majors with Avalonia 12.1 is unsupported. |
| Monaco/web editor in a WebView | Adds a Chromium/WebView dependency, JS bridge and larger redistribution/security surface for the same result. |
| Tree-sitter/Scintilla native editors | Native binaries per macOS architecture; unreviewed redistribution and no first-class Avalonia host. |
| Microsoft SQL parsers (ScriptDom/SMO) for colouring | Separate licence/redistribution review (see DEPENDENCIES.md); lexical colouring does not need them. Revisit for diagnostics. |
